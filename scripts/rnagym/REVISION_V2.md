# RNAgym evaluation and training revision (2026-10-02)

## Confirmed evaluation defect

MXfold2 exports triangular BPP entries. The historical evaluator added each
pair only to its left endpoint. Historical RNAgym chemical metrics must not
be used as corrected measurements. TestSetB BPSEQ comparisons are unaffected.

`symmetric-bpp-v2` sums each undirected pair at both endpoints, without
double-counting symmetric input. The new evaluation worker bypasses text
files entirely, sets the native BPP export cutoff to zero, and retains native
floating-point precision. Ordinary MXfold2 calls retain their 0.01 default.
An audit compares the old one-sided/rounded output, symmetric sparse output,
and symmetric full-precision output on the deterministic test 1/100 subset.
This subset is an implementation check, **not** validation for model selection.

## Three experiment tracks

1. Corrected whole-test reevaluation of the existing baseline, standard A
   IMLE-rank/2A3 and SHAPE-fy/2A3, frozen A IMLE-rank/2A3, and B
   SHAPE-fy/2A3 replay90. Existing TestSetB results are reused, not overwritten.
2. Standard baseline/rank/shape-FY training, seeds1234/1235/1236,100 epochs,
   all layers, AdaBelief lr0.001,l2=0.01,score_loss=0.125,perturb0.75.
   The baseline starts from random initialization; A models start from their
   existing RNAgym epoch5 checkpoint. This is a **fixed epoch100** comparison.
   TrainSetB curves are recorded; TestSetB is not used to pick an epoch.
   These replicate fine-tuning seeds, not independent pretraining seeds.
3. Budgeted B direction, same two2A3 methods,seeds1234/1235/1236,
   replay0/50%,from the specified TrainSetA epoch100 model.512 unique train
   sequences are held fixed;128 disjoint train sequences form validation.
   No homology-disjointness is claimed.512 draws per short epoch without
   replay,1024 draws with50% replay (512 expected chemical exposures).
   Rank accumulates4,shape-FY8; five epochs mean640/320 updates without
   replay and1280/640 total mixed updates with replay. Sampling is with
   replacement; distinct sequences seen and replay counts are not exactly
  512 per epoch. This is an adaptation-budget experiment, not a full-RNAgym
   pretraining epoch. Select0/1/2/5 on TrainSetB macroF1, ties earliest.
   Baseline0 remains an eligible candidate. RNAgym-train validation metrics
   are reported as a second objective; neither test set is used for selection.

All jobs request gpu_h=1. Standard training uses20-epoch segments, maximum
23:50h; budget jobs4h,audits6h,aggregation1h. Whole-test evaluation uses16
shards rather than8, to leave additional margin with full-precision BPPs.
Evaluation requests8h per shard: historical8-shard runs took3.1--4.4h,
and the new16-shard runs halve the sequences per task. This also reduces
unnecessary group-point reservations. Training requests remain23:50h/4h.
The known CUDA-misallocation host r22n6 is excluded. Missing CUDA is fatal.
No BPP/BPSEQ prediction files are generated by evaluation. Only one NPZ per
shard is retained until aggregation, then removed. Source results/checkpoints
are preserved; v2 results have a separate workflow directory.

## Run

```sh
.venv/bin/python scripts/rnagym/revision_experiments.py prepare --root WORKFLOW_ROOT
.venv/bin/python scripts/rnagym/revision_experiments.py submit --root WORKFLOW_ROOT
# After a partial scheduler/point-reservation refusal:
.venv/bin/python scripts/rnagym/revision_experiments.py resume-submit --root WORKFLOW_ROOT
```

`plan.json` defines every checkpoint and protocol, `submissions.tsv` records
all job IDs, `results_v2.csv` holds model-level results, and
`standard_seed_summary.csv` holds matched standard-training means/SDs.
`resume-submit` holds a submission lock, reuses recorded job IDs, and skips
only IDs explicitly recorded in `cancelled_jobs.json`. It never retries
failed training tasks or purchases points. A successful submission records
`submission_status.json`; failures record `last_submission_failure.json`.
